## 1 视频定位

| 项 | 内容 |
| --- | --- |
| 一句话卖点 | **车机蓝牙听的歌，也能有滚动歌词 —— 而且第二遍就不用再等** |
| 受众 | 车机 / Android 开发者，爱折腾车机的车主 |
| 时长 | 主版约 100 秒（素材够可扩到 3 分钟），竖版 30 秒 |
| 形式 | 车机录屏为主（像素级干净，占 80%）+ 少量实拍做"环境感"+ 后期配音 |
| 关键反差 | 别人做歌词要联网匹配歌词库；这个方案**把歌词"听"出来**，全程离线 |

**全片要讲清的三件事**（观众看完必须记住）：

1. 不接管音频 —— 声音还是车机蓝牙播放器出的，App 只是"坐在旁边看"
2. 不用联网 —— 歌词是听出来的，本地存、本地放
3. 能搬家 —— 歌词库可导出到下载目录，也能在局域网里传给手机

## 2 口播文案（100 秒版）

约 430 字，按 **4.2 字/秒** 配速，直接照读即可。

**［0:00–0:10　钩子］**

> 车机上听手机里的歌，屏幕上永远只有一行歌名，没有滚动歌词。因为蓝牙只肯传三行字：
> 歌曲名、歌手、专辑 —— 歌词不在这三行里。

**［0:10–0:22　洞察］**

> 但这里有个漏洞：网易云、QQ 音乐、哔哩音乐在手机上播放时，会把**当前这一句歌词**
> 塞进这三行里，发给系统。车机屏幕上那行"歌名"，其实就是歌词。

**［0:22–0:35　做法］**

> 所以我写了一个车机 App。它不抢音频，只做一个"消费者"：通过 MediaSession 读那三行
> 和播放位置 —— 哪一行在变，就说明歌词写在哪一行。网易云这一套、哔哩音乐那一套，
> 它自己认。

**［0:35–0:55　记忆］**

> 真正省事的是它一句一句地记：每两三秒收一句，顺手记下当时的播放位置。一首歌放完，
> 整首歌词就齐了，存成本地文件。第二遍再听，直接从本地同步显示 —— 不用联网，
> 不用等匹配。

**［0:55–1:05　数据］**

> 21 首歌、652 句歌词，一共 66 KB。就算攒到 1000 首，也只有 1.3 MB，启动读一遍
> 250 毫秒。

**［1:05–1:20　搬家］**

> 换车机怎么办？导出到系统下载目录；或者车机和手机连同一个 WiFi，点一下弹出一个网址，
> 手机浏览器打开就能下载，也能上传。歌词库是可以搬家的。

**［1:20–1:33　细节］**

> 打磨的地方也不少：15 秒内切走的歌不留记录，免得库里全是垃圾；播放位置往回抖会让
> 歌词抽搐一下，就把它压成单调的；长句缩放不截断，左边面板固定高度不跳。

**［1:33–1:40　结尾］**

> 全程不用 root、不用碰蓝牙协议，就是一个"偷听"的思路。代码开源，欢迎拿去改。

### 配音注意

- 一句里别换气太碎；0:35 之后的"记忆"段是全片重点，语速可以稍慢半拍。
- 数字念清楚：**66 KB**、**1.3 MB**、**250 毫秒**（这三个是可信度来源）。
- 车内环境噪音大，**不要在车里录旁白** —— 后期在安静房间里对着分镜表重录。

## 5 拍摄流程

### 5.1 拍前准备（决定能不能拍到"第一次"）

1. **先备份歌词库**：车机上「导出到下载」，把现有歌词导成 `lyriccar-日期.json`。
2. **准备"没记过的歌"**：找 2–3 首库里没有的歌（分镜 7 要用）。
   拍完后用「从下载导入」把备份导回去，恢复原样。
3. **清干净画面**：关掉车机语音助手浮层（它会盖住屏幕底部约 250px，还会吃掉点击）、
   关通知、连上 WiFi、**亮度固定别用自动**。
4. **别在开车时拍**：全部停车拍摄。要"在路上的感觉"就用车外机位 + 后期加速，
   绝不让镜头里的手在行驶中去点屏幕。
5. 备好充电（录屏很费电）、三脚架、擦镜布（车机屏反光）。

### 5.2 A 线：车机录屏（主素材）

车机屏幕用 `screenrecord` 直录，画质等同截图，没有摩尔纹、反光和快门条纹：

```bash
# 录一条（车机上执行，最长 3 分钟，可以中途 Ctrl+C 提前结束）
adb shell screenrecord --size 1280x720 --bit-rate 8000000 /sdcard/a01.mp4

# 拉回电脑
adb pull /sdcard/a01.mp4 ./footage/
```

每个动作单独录一条，方便剪辑；每条前后各留 3 秒静场。

| 编号 | 要录的动作 | 长度 | 用途 |
| --- | --- | --- | --- |
| A1 | 一首**已有歌词**的歌，跟唱一整段（含"回放"状态字样） | 40s | 分镜 5、6、11 |
| A2 | 一首**没记过**的歌，从第一句采集到结束 | 30s | 分镜 7 |
| A3 | 采集中途点「下一首」，再切回来 | 20s | 分镜 10 |
| A3b | **半份稿子重听**：一首只听了半分钟的歌，切走再回来 → 顶上一条「还没采完」提示，歌词立刻从头滚，缺的边放边补 | 30s | 分镜 10（最能说明「不用等采完」） |
| A4 | 打开歌词库列表，上下滑一遍 | 10s | 分镜 8 |
| A5 | 导出到下载 → 成功提示 → 从下载导入 | 30s | 分镜 9 |
| A6 | 局域网传输：点开 → 显示网址 → 手机下载 → 手机上传一份 | 40s | 分镜 9 |

### 5.3 B 线：手机实拍

- **机位 1（B1）**：驾驶位侧后方 45°，拍"人 + 车机屏"整体。三脚架，不许手持。
- **机位 2（B2）**：贴近车机屏的斜 15° 特写，只用来拍"环境光下的屏幕"。会有轻微反光，
  反而真实 —— 但**不要**用它拍歌词细节（细节一律用 A 线）。
- **机位 3（B3）**：拍手机屏幕，展示播放器把"歌名"当歌词在改。
- 固定曝光与白平衡；遮住车窗直射光；**夜间拍最干净**，白天就关车窗 + 用遮光板。
- 每次开拍前在镜头前**拍一下手打板**，后期靠这声"啪"把 B 线和 A 线对齐。

### 5.4 拍摄清单（拍完逐条打勾）

- [ ] A1–A6 六条录屏都在，能正常播放
- [ ] 手指没有挡住要展示的区域（尤其底部浮层高度）
- [ ] 拍到"状态 → 采集 / 回放"这行小字
- [ ] 拍到手机端播放器界面（证明"歌名就是歌词"）
- [ ] 三个关键数字拍清楚：导出文件名、局域网网址、歌词库句数
- [ ] 每条素材前后各有 3 秒空白，方便剪辑下刀
- [ ] 备份的歌词库已经导入回去，车机数据恢复原样

## 6 剪辑流程

### 时间线顺序

`钩子 0:00 → 原理 0:10 → 做法 0:22 → 记忆 0:35 → 数据 0:55 → 搬家 1:05 → 细节 1:20 → 结尾 1:33`

### 节奏规则

- **旁白段**：每 3–5 秒换一次画面（A 线 / B 线交替），别让观众一直盯同一屏。
- **演示段（分镜 6、7）**：**不切**，让歌词自己滚完 —— 这是全片最抓人的地方，
  BGM 在这里抬一档。
- **数据段（分镜 8）**：`66 KB` / `1.3 MB` / `250 ms` 用数字放大 + 轻微上浮动画。
- **三处快切（分镜 10）**：0.2 秒硬切，不加转场，显得干脆。
- 全片不出现超过 1.5 秒的静止画面。

### 字幕规范

- 车机 UI 是深色底 → 字幕用**白字 + 40% 黑描边**，放在底部安全区（避开浮层高度）。
- 关键词只强调一次：`歌词`、`MediaSession`、`离线`、`1.3 MB`。
- 一句字幕不超过 **18 字**，长句拆两屏。
- 竖版：字幕放大 20%、位置抬高，避开平台按钮。

### 声音

- BGM：无版权轻电子，100–120 BPM。
- 旁白段 BGM 压到 **−18 dB**；演示段抬到 **−12 dB**；结尾 2 秒淡出。
- 旁白统一在安静房间重录，不要用车内原始收音。

### 画面

- A 线录屏**不调色**（保证 UI 颜色真实）。
- B 线实拍统一降饱和 5%、提一点对比，把屏幕亮度"托"出来。
- 手机屏和车机屏做分屏时，两边都加细边框，避免糊成一片。

### 导出

- 主版：H.264 / 1080p（1280×720 上采样）/ 60fps / 8–10 Mbps。
- 竖版：中间裁切 + 放大字幕，**不要拉伸**。

## 附录 B 标题与简介候选

起名的思路只有一条：**先摆出「这不合理」的那一幕，别先把技术讲出来**。这个项目最抓人的
三个事实是 —— ① 车机蓝牙屏上永远只有一行歌名；② 歌词其实就藏在那三行字里；
③ 不用 root、不用联网，第二遍还有记忆。

### 主标题（用这个）

> **不用联网、不用 root：让车机蓝牙歌也有滚动歌词**

三个限制词把「要不要拆车、要不要会员、要不要网络」直接回答掉，是转发时最省事的一句。

### 备选（按风格挑，各平台不一样）

| 风格 | 候选标题 | 适合 |
| --- | --- | --- |
| 痛点共鸣 | 车机蓝牙听歌，屏幕上永远只有一行歌名 —— 我自己写了个 App 把歌词找出来了 | B 站（主推备选） |
| 痛点共鸣 | 车机屏那么大，歌词却只有一行 | 抖音 / 小红书 |
| 痛点共鸣 | 开车听歌没歌词太难受了，于是我自己做了一个 | 小红书 |
| 悬念技术 | 蓝牙只肯传三行字，我却让它显示了整首歌词 | B 站 |
| 悬念技术 | 蓝牙协议只传三行字，歌词是怎么「藏」进去的 | B 站 |
| 悬念技术 | 我让车机「偷听」出了整首歌词 | B 站 / 知乎 |
| 成果直给 | 一首歌放完，歌词自己就齐了 | 短视频 |
| 成果直给 | 第一次听边听边记，第二次听直接同步 —— 车机歌词 App | B 站 |
| 折腾党 | 给爱折腾车机的人：全屏滚动歌词，装上就能用 | 车友群 / 论坛 |
| 逆向味 | MediaSession 的另一种用法：从蓝牙三行字里把歌词捞出来 | 掘金 / GitHub |
| 数字实证 | 21 首歌攒成 66 KB：歌词库能导出、能局域网传 | 知乎 |
| 反差 | 不接管音频、不碰蓝牙协议，就这么「偷看」出了歌词 | B 站 |

**起名公式**（自己再派生）：`反常识事实` + `我做了什么` + `一个限制词`

### 封面

车机全屏歌词实拍 + 一句大字。大字备选（4–6 字，比标题还重要）：

- **车机也有歌词了**
- **歌词藏在这三行里**
- **不用 root · 不联网**
- **第一次听就记住了**

封面上那三行小字（歌曲名 / 歌手 / 专辑）**别放太小** —— 那是「秘密」本身，要让人看清。

### 分平台适配

| 平台 | 长度 | 用哪一类 |
| --- | --- | --- |
| B 站 | ≤ 30 字，**前 15 字决定生死** | 悬念技术型；主标题 + 副标题用「｜」分隔 |
| 抖音 / 小红书 | ≤ 20 字，口语化 | 痛点共鸣型；别出现 `MediaSession` |
| 知乎 | 提问式 | 「如何让车机蓝牙音乐显示滚动歌词？」 |
| GitHub / 掘金 | 技术词可以放开 | 逆向味那条 |

### 三个坑，别踩

1. **别写「破解」「免费解锁 VIP」** —— 既不符合事实（本 App 只是读系统媒体信息），
   也有被判违规的风险。
